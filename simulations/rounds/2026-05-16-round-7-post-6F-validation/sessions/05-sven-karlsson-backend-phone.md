## 6. Bugs / structural defects

1. **6A AWS softener fires the "returner shape" framing on the moved-off-deliberately case.** Per `scoring.ts:154-166`, the softener triggers whenever `tech.enterpriseStillUsed && seniority !== 'junior'` AND coverage-resolved color is non-Green AND lastUsed is stale/ancient. The note text — *"Stale (2-4 yr) but was contemporary at last-use — returner shape; expect ramp-up rather than concern."* — bakes in a returner narrative even when the candidate (a) is currently employed, (b) deliberately moved off the tech, (c) didn't take a career break. The 6C junior-gate closes the Mei case (junior + team-hasn't-upgraded), but Sven's **mid-senior-moved-off** case is structurally the same misfire one ladder up. **Severity: Medium.** Proposed alternative wording (see Recommendations R1 below): drop the "returner" claim entirely; the asymmetric softener is correct (Red → Yellow IS the right verdict) but the *reason* should be neutral: *"Stale (2-4 yr) but the version was current at last use — defensible legacy or deliberate move-off; probe which."*

2. **Backend template has no `methodologyChips`** (6F deferral). Confirmed at `roles.ts:62-76`. Sven's senior signal (contract testing / feature flags / OTel / idempotency / MVCC patterns) all lives in methodology. With chip-less Backend + free-text fallback, **the recruiter captured 4 of 5 methodology entries** in this session — but only because she's a competent recruiter scrolling back up. **A junior recruiter would capture 0-1.** The fallback hint copy ("release automation, A/B feature flags, MVVM, threat modelling") shows **0 backend-shaped examples**, reinforcing the read that "this section is for other roles." **Severity: Medium-High.** Backend recruiters working chip-less get 60-80% less methodology signal than Mobile/Frontend recruiters working with chips — even though both groups have the same free-text input available. **The hint copy is the cheap fix; chips are the deep fix.**

3. **K8s `enterpriseStillUsed: true` is a catalog flag mismatch in 2026.** Per `technologies.json:1316`, K8s carries the root `enterpriseStillUsed: true` flag. The flag was designed for "Java 11 / PHP 7 / Spring Boot 2.5 — still common at enterprise clients, defensible legacy." Kubernetes-in-2026 is **the modern default**, not legacy. The note "Still widely used in many enterprise applications" firing on an unknown-version K8s card (Sven's case — he doesn't know the cluster version) is filler. **Severity: Low** (it's a small per-card noise), but it points at a broader catalog-audit need: which of the ~20 `enterpriseStillUsed: true` flags actually warrant the note in 2026? Same finding raised in round-6 Priya's R6 — still open. **Sven re-confirms it on a different tech (K8s vs. Kotlin).**

4. **K8s is version-mode but Sven's actual shape (Helm-chart consumer) is naturally checklist-shaped.** Sven's K8s knowledge maps to a service-list: ["values.yaml editing", "resource limits/requests", "probe configuration", "kubectl exec for debug", "kubectl logs", "rolling deploy via Helm"] — NOT to "knowing K8s 1.28 vs 1.33 features." The version-mode card forces him to either guess a version (false signal) or click "I don't remember" (forfeits any specificity). **For a deploys-but-doesn't-author candidate (a huge chunk of mid-Backend in 2026), K8s-as-version-mode is the wrong shape.** Promoting K8s to **hybrid mode (version + checklist)** would let Sven tick the 4-5 services he actually uses, get an honest Yellow (`4/10 services + scope=operator → Yellow`), and avoid the false-confidence-via-version-guess path. **Severity: Medium**, recurring in spirit with the round-1-through-5 coverage-as-single-axis cluster but in the opposite direction (version-as-only-axis under-serving operator-shaped candidates). This is **the version-mode mirror of 5λ/6D's checklist-mode redesign**.

5. **No 5th scope option for `consumer` / `values-tuner`.** Per `scoring.ts:494-501`, Scope options are operator/author/reviewer/architect. Sven's K8s shape ("I edit `values.yaml` on someone else's chart") doesn't fit any. The round-2 Fix N proposal (`scope=consumer / triggered-by`) is still `⏳` in RESUME.md. **Severity: Low-Medium** (workaround: leave scope blank → operator-implied → less wrong than picking architect/author/reviewer). Sven sharpens the case — `consumer` would be the right scope for *editing config in someone else's IaC*.

6. **Backend GuidancePanel + suggestedProbes don't anchor on methodology.** Per `technologies.json:488-492`, Spring Boot's `suggestedProbes` = ["Reactive (WebFlux) or traditional MVC?", "Virtual threads experience?", "Native image / GraalVM?"]. **All three are tools/features questions.** Zero of them prompt the recruiter to ask about contract testing, observability discipline, idempotency, MVCC patterns. The GuidancePanel doesn't compensate for the missing methodology chips on Backend. Compare Mobile's chip set (release automation / MVVM / A/B / Crashlytics / ABI / offline-first — 6 senior-mobile methodology surfaces); Backend has neither chips NOR probe-text hints. **The Backend recruiter is doubly chip-less.** Severity: Medium.

7. **The "Other in these categories" prompt at the bottom of Assessment is doing real work here.** Without it, Flyway + Testcontainers would not have been captured (Sven didn't volunteer them; recruiter prompted via the yesterday-`72f6810` prompt). Worth flagging as **a fix that's load-bearing for Backend specifically** — backend candidates have long tail libs (Hibernate / Mockito / Maven / Gradle / Liquibase / Awaitility / Resilience4j) that no template can preload. The prompt is the only path to capture them.

## 10. Disagreement with prior fixes

The 6F focused-subset scoping ("only chip Mobile and Frontend because they were the loudest complaints") is **defensibly prioritized by visible noise**, but it implicitly **discounted Backend because no Backend recruiter had complained yet** — not because Backend was healthier. Round-1 Hiroshi was scored by a tool that didn't have a methodology section at all (D4 was a structural defect, not a missing chip-set); round-5 Margarethe was scored by 5α-ε AWS / Java softener logic on the *returner* axis (not the senior-engineering axis). **Round 7 Sven is the first Backend session where methodology capture has been the load-bearing signal AND the chip-set has been absent AND the recruiter has had the bandwidth to notice it.** The 6F deferral wasn't wrong by the data available; it's wrong by the data available *now*. **6F was right to defer Custom (any chip-set is wrong for "Custom"); it was wrong to defer Backend.**

The narrower disagreement: the 6A softener's reason text ("returner shape; expect ramp-up rather than concern") was lifted directly from Sarah's round-3 wrinkle (returner who left in 2022 on Spring Boot 2.5). At the time, "returner" was the canonical case for stale-Red-with-enterprise-flag and the wording was a tight fit. But adding 6A's AWS / Azure / GCP `enterpriseStillUsed: true` flag (in round-6) opened the softener to **non-returner** shapes: mid-senior engineers who used a cloud service once and moved off, junior engineers on a team that won't upgrade (closed by 6C), career-switchers who touched cloud in their bootcamp project. The reason text was never re-audited for these new shapes. **6A as a verdict-color change is correct; 6A as a hardcoded narrative is brittle.** R1 above (neutralize the reason text to "defensible older usage; probe which") is the right shape; R1 was not in the 6A ticket because the 6A ticket inherited Sarah's wording without re-validation against 6A's broader trigger conditions.

The cleanest pattern this surfaces: **when a softener / penalty fires, the verdict-color logic and the reason-text copy should be considered independent decisions.** 6A correctly identified that AWS/Azure/GCP deserve the asymmetric softener axis; 6A incorrectly reused the round-3 returner-specific copy across a broader trigger surface. A small refactor of `recencyNote` to take a `scenario` enum (returner / moved-off / team-won't-upgrade / generic) with a per-scenario template would be the principled fix — but R1's neutral-wording approach is the pragmatic fix that costs 5 lines.
