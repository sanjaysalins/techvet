## 10. Disagreement with prior fixes

The 6F Mobile ship is **half-right, half-asymmetric**. The SwiftUI + Jetpack Compose catalog promotions are unambiguously the right call — closes round-1 Alex Tan + round-6 Priya simultaneously. The Mobile methodologyChips addition closes the round-6 "Mobile is the only non-Custom template without chips" gap. **What's wrong with 6F:**

1. **SwiftUI shipped without UIKit.** For 2026 iOS, the UIKit→SwiftUI migration is the canonical senior-iOS narrative; shipping only SwiftUI captures only half the story. UIKit was on the round-2 Fix I deferred list explicitly. Should have shipped as a pair. Same logic applies to Jetpack Compose / XML Views (Compose shipped without an XML-Views catalog companion — that's a parallel gap on the Android side).

2. **Mobile preload scaled in the wrong direction.** Round-6 Priya R3 recommended a stack chooser (cut preload to 1–3 cards based on candidate platform). 6F scaled preload **up** (5 → 7 cards) by adding Compose + SwiftUI directly to the preload list, which means every single-platform Mobile candidate now dispatches 5 not-in-stack cards instead of round-6's 4. The catalog promotions were right; the preload addition was wrong. A correct ship would have **added Compose + SwiftUI to the catalog but kept Mobile preload at 5 platforms** (or implemented R3's stack chooser).

3. **Mobile methodologyChips chose cross-platform-leaning chips over platform-specific ones.** Crashlytics, ABI splits, offline-first all skew Android/cross-platform. Crashlytics+ABI specifically conflict with native-iOS practice (Apple's Xcode Organizer vs Firebase; iOS doesn't have ABI). The chip set was authored for *generic mobile* rather than *iOS native + Android native + cross-platform all served*. **Recommend a 9-chip Mobile set** that covers all 3 platform shapes: 3 iOS-canonical (MVVM-C, snapshot testing, VoiceOver), 3 Android-canonical (MVI, Compose state hoisting, TalkBack), 3 cross-cutting (release automation, A-B/feature flags, crash reporting). That's parity with DS at 9 chips and doesn't penalize any specialist persona.

The narrowest disagreement is on **(2) above**: the 6F Mobile template diff added 2 techs to preload (`jetpack-compose`, `swiftui`) without an offsetting reduction. For a Mobile recruiter screening any single-platform candidate (which is most Mobile candidates), 6F made the 0–30-second "is it X? no" loop measurably longer rather than shorter. The correct ship was **catalog entries without preload addition** OR **catalog entries + stack chooser**. Either alternative would have left Kenji with 2–3 preloaded cards relevant to his stack instead of 7 with 5 to dispatch.
